# Проверки доработки от 27 сентября 2026 года

- Ruff: проверка правил и форматирования прошла для backend.
- mypy: ошибок в 14 модулях исходного кода нет.
- pytest в контейнере с PostgreSQL: 19 тестов прошли.
- Проверены два независимых API-процесса, восстановление подписки по курсору,
  изоляция исполнителей, переназначение, отзыв роли и активности, истечение JWT.
- Конкурентные одинаковые запросы создают одну заявку и одно уведомление.
  Из двух изменений одной версии проходит одно. Ошибка записи журнала откатывает заявку.
- В тестовой БД выполнены откат и повторное применение новой миграции;
  контрольная сумма пользователей, площадок, заявок, аудита и ключей повторов совпала.
- Frontend: линтер, TypeScript, форматирование изменённых файлов и сборка прошли.
- Полный Compose-стенд запущен; API, frontend и PostgreSQL прошли healthcheck.
  Runtime API использует UID 10001; порты доступны только на loopback.
- Diff проверен; известных форматов приватных ключей и служебных токенов в изменениях нет.

В Chrome вручную проверены экран входа и успешный вход диспетчера: загрузились
сводка, демозаявки и индикатор Real-time. Проверка выявила отсутствие
`type="submit"` у кнопки входа; после исправления отправка формы работает.
Дополнительно проверены переход к списку заявок, поиск по названию, пустой
результат поиска, открытие формы создания и сообщения об обязательных полях.
Создание заявки через браузер и смена статуса в интерфейсе не проверены:
канал управления окном нестабилен; выбор объекта завершить не удалось.
Эти операции на уровне API покрыты автоматическими тестами.
Нагрузочные пределы, восстановление PostgreSQL из резервной копии и кластерная
отказоустойчивость не проверялись. Результаты не подтверждают production-эксплуатацию.

CI выполняет проверки для каждого коммита:
[GitHub Actions](https://github.com/dasferwer/fieldops-cloud/actions/workflows/ci.yml).

## Retention и reconnect: 9 октября 2026 года

- Изолированная PostgreSQL 17: 29 backend-тестов прошли (включая два реальных
  Uvicorn-процесса и WebSocket). Новые проверки покрывают dry-run, размер пакета,
  границу replay, пустой журнал, атомарный rollback, очистку между SQL-запросами
  читателя и отказ downgrade после удаления. Предел replay 10 000 сохранён.
- На свежей тестовой БД проверен обычный downgrade/upgrade; предметные данные
  сохранились. Та же проверка прошла после полного pytest: retention-тесты
  восстанавливают свой журнал отдельной тестовой fixture.
- Ruff и форматирование backend, mypy (15 модулей), frontend lint, TypeScript,
  форматирование двух основных frontend-файлов и production build прошли.
- В отдельном контексте Chrome заполнен черновик формы, включён Offline и остановлен
  API. Пока соединение было потеряно, изменена заявка и удалён её старый сигнал.
  После запуска API и восстановления сети появился Real-time и актуальный заголовок
  заявки; оба текстовых поля открытого черновика сохранились. Код frontend не менялся.
- Смена роли подключённого диспетчера закрыла поток и вернула экран входа.
  После входа с ролью техника чужие заявки отсутствовали (0 доступных заявок).
- После reload авторизованной вкладки восстановились пользователь, 13 доступных
  заявок и Real-time; REST-запросы вернули 200, ошибок и предупреждений в консоли нет.
- Синтетический журнал: 10 000 просроченных сигналов и один недавний, один cleaner,
  пакет 1000, PostgreSQL 17 в Docker, Python 3.12.13/macOS ARM64. Dry-run показал
  1000 кандидатов и 0 удалений. Десять пакетов удалили 10 000 сигналов за 0,124 с,
  оставив недавний; максимальное время пакета 0,0143 с, пик Python allocation
  528 241 байт, RSS процесса 76 857 344 байта. Это локальный замер очистки,
  не нагрузочный тест подписок и не production SLA.

Автоматический scheduler не добавлен. Не проверялись массовые подписки и
восстановление БД из резервной копии. Сохранение черновика относится к reconnect
в открытой вкладке; перезагрузка страницы черновик не сохраняет.
